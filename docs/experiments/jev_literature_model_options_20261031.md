日期：2026-10-31。状态：**文献核验与设计建议，不是新模型训练或效果认证**。本轮 D6 异步执行改动按原授权独立验证；以下新研究方案不自动替换冻结模型、划分或正式测试协议。

公开检索工具在本轮返回后端404；改用只读HTTPS访问arXiv原站，成功核验下列论文标题与作者摘要。重点进一步读取了JEV-as-a-Judge v6的HTML协议/置信度相关段落。其他条目不声称全文复现，更不根据综述推断无人机实验效果。综述截图与现版本可能不同：该Judge论文已于10/29修订为v6，其当前摘要中的独立配对数等与截图不同，因此不沿用截图数值或阈值。

## 2. 对照当前实现后，优先处理什么

### P0：概率来源和含义，先于调低回退阈值

当前 [`selector.py`](../../src/jev_uav_track/selector.py) 有confidence/top-probability/margin门槛，默认分别为0.55/0.45/0.08，尚不是UAV动作成功率校准。

本轮只读最小诊断发现 [`jev_client.py::_parse_decision`](../../src/jev_uav_track/jev_client.py) 在回复缺少概率时，会为返回的choice补one-hot；其confidence仍可为None，而selector允许None通过confidence检查。实际本地输出：

```text
input: {"next_behavior": "hold"}, valid_ids=["hold", "left"]
output: probabilities={"hold": 1.0, "left": 0.0}, confidence=None,
        top_probability=1.0, margin=1.0
```

这是兼容格式，不是服务报告的100%把握。若用它拟合置信度或判断收益，会把“缺信息”变成“高置信”。本轮未修改既有选择器；这应作为新置信度方案前的接口硬化项：

- 区分 `native_probability`、`synthetic_one_hot`、`missing` 等来源；缺失/非法信息不得计作校准概率。
- 检查选择ID与概率排序的一致性、所有概率/置信度有限且范围合法；未知/不一致回复进入有原因码的受约束回退。
- Utility的一热输出是确定性算法编码，不能与Jev的概率质量混合统计。
- 区分“Jev回退到utility”“rollout回退到透明模型”“安全测量缺失而不发命令”。三者不是同一类失败。

该诊断不表明历史两次真实Jev回复一定存在此缺陷；也没有发送任何API请求。需要独立测试和协议版本后再改变生产行为。

### P1：风险可控的选择性接受，而不是单看Jev置信度

保留架构：因果belief -> 同一候选集 -> rollout -> 本地硬安全过滤 -> Jev/utility -> 当前测量复核 -> 受约束控制。

拟议接受条件是**同时**满足：输入/回复新鲜；当前安全测量有效；候选在rollout支持域且区间可接受；Jev概率具有真实来源并达到本任务校准要求。它们分别代表不同不确定性，不互相替代。

先报告risk-coverage（采纳比例与采纳后的错误/风险）、校准曲线/Brier、无效回复率、过期率、回退原因、调用成本，再决定阈值。动作结果标签只来自真实执行后果/经过审核的对照，不能把Jev自己返回的choice当正确标签。当前39集记录动作数据可继续校准对应已执行动作的rollout，但不能给全部未执行候选制造成败标签。

校准只能在既有fit/calibration权限内进行，validation只评估，stress/Town03不回流。现有calibration没有充足Jev动作结果标签，所以**现在不拟合或宣称该门控已提升效果**。校准不确定性应以episode为独立单位，不能把连续帧都当独立样本。可选加入同调用预算的随机路由对照，检验收益来自置信度信息还是仅来自调用比例。

### P2：事件型因果记忆，保留短时窗口

[`history.py`](../../src/jev_uav_track/history.py) 已有8帧有界窗口、自运动、可见性与身份摘要；[`causal_belief.py`](../../src/jev_uav_track/causal_belief.py) 已用历史可见测量推断运动。Jev-Mem的启发是增加少量**事件**，而不是不停追加长文本：最后一次可靠看见的时间/方位；遮挡开始；上一次受约束搜索方向及观测结果；身份关联冲突。

建议新增独立事件缓存，限定容量、时间跨度和检索数；按当前时间t只读<=t信息，重置episode时清空。目标ID只能来自明确标注的可用观测/关联器；旧可见actor-oracle保持oracle标签，不得升级为RGB ReID证据。未执行动作不能写成成功/失败记忆，未来帧和隐藏位置不能写入缓存。

先以合成因果回归检查“修改未来帧不改变t决策”“跨episode不串记忆”“身份不确定不继承旧速度”，再等待真实遮挡/交叉PASS样本做效果对照。目前可见576、遮挡/出框0的验证集不足以证明事件记忆收益。

### P3：Jev用于高层建议，50ms本地控制不能等待网络

这是与D6原计划重合、已在本轮实现并另行验收的部分：单个未完成请求、有界后台工作线程、generation重置、200ms过期丢弃、50ms受约束命令前缀、当前安全测量复核。参见 [`async_control.py`](../../src/jev_uav_track/async_control.py) 和 [本轮验收](d1_d6_acceptance_20261031.md)。

正常/延迟/超时Mock只验证控制逻辑；不是网络延迟实测，也不是CARLA闭环。历史真实Jev两条回复约2.1–2.3s，在当前200ms动作时效门槛下均未执行。不能仅改成异步便声称问题解决，更不能放宽时效门槛凑采纳率。若此延迟长期存在，下一设计应把远程输出限定为慢速搜索/跟踪意图，并由当前本地状态重新生成动作；这需要新的意图契约和独立验证，不在本轮悄悄启用。

### P4：有执行反馈后再训练轻量偏好模型

可借鉴JevVLA：在冻结透明/残差rollout上训练小型候选评分头，以实际动作结果或同初始条件的可审计配对偏好为监督，比较它是否比固定utility更会排序。Jev选择/分布可作教师建议单独保存，但不是结果真值。先评估小MLP/线性排名头，再决定是否需要LoRA；当前无反事实覆盖时不为所有候选伪造排序标签。

这一训练扩展超出本轮D6代码验收；需先准备开发地图动作后果数据与冻结协议，再单独执行。Town03仍是保留测试，不作训练来源。

## 3. 最小验证顺序与消融约束

1. 概率来源/格式硬化和审计测试；不增加网络调用，不改冻结权重。
2. 完成D6执行层回归；utility、Mock、real使用同低层控制器/动作时长/候选输入。
3. 取得开发用动作后果与困难事件PASS证据后，分别做“原门控 vs 校准门控”“短窗口 vs 短窗口+事件记忆”。基础utility与Jev保持同输入同rollout，禁止多模块一起改后归因给Jev。
4. 方法与协议冻结后再做独立Town03效果验证；真实Jev调用预算单列。每个失败、超时、回退与seed都保留，不能只挑改善的种子。

以上是待验证假设。D1–D6仍按原条款验收，不能用新增论文笔记替代独立PASS数据、困难场景覆盖或真实仿真证据。
