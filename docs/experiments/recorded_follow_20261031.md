## 为什么还不能宣称模型提升

- 四段使用同一seed `2026103001`，不是四个独立随机seed。参数和控制版本也不全相同；本轮不做显著性或跨方法胜负排名。
- 都是可见时仿真器提供位置的`visible-oracle`，车辆由脚本驱动，不是RGB检测器或真实多目标交叉；身份保持NOT_AUDITED。
- 归档模型SHA为`a4fbeb5590d3d9e154f793ee2a702ae49a44c89dff4997e712fd17ebeb451000`，本轮对原模型文件只读重算一致。它不是当前本聊天因果D5模型`b67c0a70...`，历史oracle训练限制不能被录像消除。
- 视频使用`d5-residual-pessimistic-tracking-envelope-v1`，明确是不同于原D5全回退门控的新控制器。后3段速度上限1.2m/s，前缀至多100ms、Jev行为回复可复用3s；不符合当前D6固定0.3m/s、50ms前缀与200ms新鲜度的同一执行配置，不静默复制这些放宽参数。
- 真实Jev回复延迟中位数分别1.691/1.635/1.610/1.609s。归档通过异步高层行为＋新观测反馈工作；不能把秒级旧建议当200ms以内的直接动作。当前D6若直接等待此API会过期，必须明确区分建议、当前动作及回退来源。
- 非Jev时段使用本地模型utility。没有同初始条件、同控制器的透明+utility / residual+utility / residual+Mock / real Jev配对基线，无法归因高可见率。较快/转弯阶段约71%–79%的已ACK前缀不是Jev来源。
- 持续跟随证据不是训练PASS接纳。Town03独立PASS增量0，所有这些开发运行仍NOT_AUDITED，不进入训练或final-test manifest。
